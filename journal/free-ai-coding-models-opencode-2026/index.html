Free models.
Expensive mistakes.

OpenCode currently lists DeepSeek V4.1 Flash, GLM-5.3 Flash and Nemotron models as free. That can change the economics of prototyping. It does not make the project, or the data you share, risk-free.

Sovtiva ResearchNovember 12, 2026Source-backed editorial research

The screenshot going around is almost right, which makes it more interesting. OpenCode really does list several coding-capable models at a zero token price. But there are two kinds of free: a tool that costs nothing to try, and a system that is economical to operate after someone depends on it.

The difference begins with one question: what would have to be true for the software to work again tomorrow?

What's actually free right now?

OpenCode is an open-source coding agent available through desktop and terminal interfaces. Its official model catalog, checked on November 12, 2026, lists DeepSeek V4.1 Flash Free, GLM-5.3-Flash Free, and Nemotron 3 Ultra Free among other temporary offers. The vendor labels these promotions free for a limited time. A discontinued free model or a different client can change what you can access.

There is another distinction worth making: a free model shown inside OpenCode is not necessarily a free API for our own SaaS product. OpenCode says its free-tier chat models must be used through the OpenCode client. Other integrations may require a paid model, a separate provider or a different license.

Free-model descriptions should be read per provider, not as one blanket privacy promise. OpenCode's own privacy section identifies other free models whose inputs may be retained or used for improvement. Before accepting client code, a company should check the current provider terms, its contractual obligations and its own access controls.

What a free model can reasonably build

The strongest initial use is a bounded, reversible piece of software: a sample-data intake form, a CSV cleanup script, a testable pricing calculator or a simple landing-page component. It should have clear acceptance criteria and no live customer secrets. These are suggested pilot workloads, not claims that Sovtiva tested or shipped them with these specific models.

01 / SPECIFY

One small job

Define the input, expected output, failure cases and acceptance test before prompting.

02 / ISOLATE

Safe inputs

Use synthetic data and a throwaway branch or sandbox. Keep production credentials out.

03 / VERIFY

Run the tests

Check functions, edge cases, security issues, responsive layout and accessibility.

04 / OWN

Keep the source

Record dependencies and pin versions. Confirm a second person can reproduce the result.

The hidden cost is the second week

Consider a scheduling assistant built in an afternoon. Its first demo looks polished. Then someone changes the intake form, a calendar permission expires, the AI guesses a missing field, and no one notices that confirmations stopped arriving. The tokens may have cost zero. The operational failure is real.

For a useful comparison, measure the whole job: time to a working artifact; defect correction; tests; deployment and rollback; model availability; support time; and data-handling obligations. Record those figures on a single small benchmark task before choosing a stack. A model that is slightly slower but produces maintainable code can be cheaper to deliver.

Our research boundary

This review verifies product descriptions and provider policies as of publication. It is not a controlled speed benchmark, production deployment, free-tier uptime guarantee or claim of paid client work. Recheck the catalog and privacy statements immediately before using a model.
