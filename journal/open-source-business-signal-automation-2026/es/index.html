Una alerta
no es una oportunidad.

Cuatro proyectos pueden detectar cambios, recopilar información y mover tareas. El criterio para convertir un dato en una acción comercial sigue siendo imprescindible.

11 de noviembre de 2026Investigación independienteImplementación pendiente de pruebas

Una empresa publica una nueva integración, abre otra sucursal o anuncia una contratación relevante. Un programa puede detectar el cambio. Saber si conviene hablar con esa empresa es otra tarea.

Encontramos cuatro proyectos públicos que permiten construir una cadena de investigación: changedetection.io observa páginas, Crawl4AI extrae hechos, Activepieces conecta sistemas y Browser Use automatiza interacciones de navegador autorizadas. Ninguno comprueba por sí mismo que exista presupuesto, intención de compra o permiso para contactar.

changedetection.io: vigilar sin ahogarse en alertas

El software identifica cambios en páginas web y puede enviar avisos mediante correos o webhooks. Sirve para observar precios públicos, documentos de integraciones, páginas de socios o anuncios de contratación. También permite reglas y resúmenes basados en IA. El problema aparece cuando todo cambio se considera importante: un pie de página actualizado no necesariamente cambia una decisión comercial.

El piloto adecuado sería vigilar tres páginas públicas autorizadas. Cada alerta debe guardar la URL, el contenido anterior y nuevo, la hora y el motivo por el cual importa. Luego descartar modificaciones irrelevantes. El repositorio usa Apache-2.0; eso facilita reutilizar el código, pero no elimina costos de alojamiento, mantenimiento y solicitudes a modelos.

Crawl4AI: extraer información sin inventar certeza

Crawl4AI convierte páginas en Markdown y datos estructurados. Puede ejecutarse con Python o Docker y también cuenta con servicios alojados. Para investigación comercial, permite extraer una descripción de servicios, ubicaciones, requisitos públicos o menciones de software con mayor consistencia que copiar y pegar.

El extractor puede equivocarse: una fecha podría ser la actualización de la página, no la del evento; una marca citada como cliente podría confundirse con la empresa propietaria. Cada dato importante exige fuente, fecha de consulta y un indicador de incertidumbre. La licencia Apache-2.0 tampoco concede acceso a páginas bloqueadas ni autoriza ignorar términos de uso o límites de tráfico.

Activepieces: automatizar la coordinación, no el juicio

Activepieces reúne conectores, flujos visuales, condiciones, reintentos, versiones y aprobaciones humanas. Un webhook podría llegar desde el monitor, consultar datos ya registrados, detectar duplicados y abrir una tarea de revisión. Su base comunitaria es principalmente MIT, con componentes empresariales licenciados por separado.

El detalle más valioso se llama idempotencia: si el mismo evento llega tres veces, se registra una sola oportunidad. También hace falta un estado visible para errores, una política de acceso a credenciales y un punto donde el flujo se detenga cuando falte evidencia. Automatizar mensajes salientes sin revisión sería una mala primera implementación.

Browser Use: cuando no existe una API

Browser Use permite que un agente interactúe con un navegador mediante Chrome DevTools Protocol. Puede resultar útil para tareas administrativas repetitivas y autorizadas en sitios sin una API adecuada. El código es MIT; su oferta comercial de nube es distinta.

Es el componente de mayor riesgo operativo de esta selección. Cambios en una pantalla pueden causar clics equivocados. Un sitio puede mostrar instrucciones maliciosas que el agente debe ignorar. Hace falta limitar dominios y acciones, aislar sesiones y exigir aprobación antes de escribir, publicar, comprar o enviar datos. Siempre que exista una API oficial estable, conviene evaluarla primero.

Una aplicación comercial concreta sería vigilar los cambios en páginas de software empresarial, verificar que la empresa coincida con el perfil buscado y presentar al equipo un resumen con pruebas. A partir de ahí alguien decide si existe una conversación legítima. Una señal pública no debe convertirse automáticamente en un prospecto interesado.

La prueba que proponemos

Tres fuentes, cero contactos automáticos, un registro de evidencia. Medir alertas pertinentes, duplicados, minutos de revisión y decisiones que sí cambiaron por la información obtenida. Esa es una prueba de valor más sólida que contar páginas rastreadas.

La economía real

Un proyecto abierto puede evitar tarifas de licencia y aun así consumir dinero en servidores, actualizaciones, navegadores, APIs y soporte. El indicador clave debería ser cuántas decisiones comerciales válidas se producen por hora de trabajo, no cuántas tareas ejecuta la IA. En Sovtiva aplicaríamos esta arquitectura primero a investigación interna y socios, sin mezclar datos privados de clientes o de otros empleadores.
