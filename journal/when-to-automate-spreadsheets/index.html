Should this spreadsheet be automated?

Not every repetitive spreadsheet deserves a script. Some need a cleaner process. Some need a better template. A few really do need automation.

The useful question is not “Can we automate it?” Almost anything can be stitched together with enough time. The better question is: “What will still work when the person who built this is on vacation?”

Here is the seven-question test we use to think through that decision.

1. Does the work happen the same way twice?

Automation needs a recognizable pattern. If every run follows a different set of undocumented judgments, record the decisions first. A three-minute checklist may do more good than a brittle integration.

2. What triggers the work?

Be specific: a new row, a weekly export, a form submission, a closed deal, or a message from a customer. “Whenever someone remembers” is a process problem, not a technical trigger.

3. Where does the source data actually live?

A spreadsheet may be the visible work surface while the real source is a CRM, inbox or vendor portal. Identify which system owns each field. Otherwise the automation can make conflicting copies faster.

4. Which exceptions matter?

List the strange cases: empty IDs, duplicate records, mixed currencies, bad dates and requests that must go to a human. A useful workflow catches those cases and says what happened. A dangerous one silently skips them.

5. What should the result look like?

Define the output before the build. One clean report? Updated CRM fields? A notification with the records that failed? If success is not observable, nobody will know whether the automation helped.

6. How much time or risk does it remove?

Estimate honestly: runs per month × minutes per run, plus the cost of errors or delays. Compare that against build, review and maintenance effort. A task repeated four times a year may be easier to document and leave manual.

7. Who owns it after launch?

Choose an owner, a place to see failures and a way to stop or fix the workflow. “It runs automatically” is not an ownership plan.

A simple example

Before: Every Monday, someone downloads three exports, copies values between tabs, removes duplicates and emails a summary.

Possible first improvement: Agree on stable source files and column names, define duplicate rules, then build one repeatable consolidation step with an exception report. The email can come later.

Why this order: It makes the data reliable before adding another moving part.

What to do with the answers

  • Stable inputs, rules and outputs: a small automation is worth scoping.
  • Unclear rules or inconsistent data: simplify and document first.
  • Rare task with low downside: a better template might be enough.
Automate the decision you understand. Fix the decision you don't.
